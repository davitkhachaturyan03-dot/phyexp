Evaluation layer (PhAIL primitives)

The PoC can now measure a policy the way PoC §3 prescribes. Time-to-success curves with censoring, HRT against a corrected human reference, per-sub-task times, episode-clustered CIs and a macro-KS gate are validated against PhAIL's own code on PhAIL's released real-robot data. On LIBERO, every rollout carries one return per metric, the input attribution needs. The answer-key leak is closed. Full-scale SmolVLA training and the 1000-rollout evaluations are scripted and wait for a server.

It reproduces the paper's per-object HRT and AUC exactly and its "four scalars, three winners" table (GR00T / OpenPI / GR00T / ACT). Per-metric attribution readiness. Every LIBERO rollout gets one return per PoC yardstick: F(30 s), RMST(60), AUC vs human, a linearized HRT(60) and the censored tail. Open decisions and known issues

  1. N1. Scratch-store tests write their outputs into the real data/eval/ (verify_run's and eval_run's default out_dir ignore lineage_root). They should default under the scratch root.

  3. N3. The batch-plan guard compares batch size, tasks, init states and seed, but not τ_episode, render size or device.
  4. N4. Leftovers for owner cleanup: data/lineage_scratch/r2, s5 (2.3 GB), s5.pre-refactor-n5, s5.refactor-n5-diagnostic, the refactor's scratch stores, and data/scratch/refactor_baseline/.
  5. N6, done. verify_verdict_s7.py --phail-seeds applies the r3 criterion (285bb62). It still prints the superseded rule, labelled. The stored s7_ac7_1_seed_sweep_stdout.txt predates N6; the current lines are in summarizer_rerun_stdout.txt.
  6. F1, refreshed. The committed AC6.3 artifact had round 1's AUC column order. On 2026-10-11 it was replaced with the refactorer's regenerated copy: only the two AUC columns swap.
  7. F2. An eval run's trajectories digest names a physical copy (LeRobot writes stats.json keys in varying order). If attribution needs a content-stable trajectory id, it should hash frames, as catalog.episode_content_hash does.
  8. Stochastic-policy outcomes depend on the batch plan (measured on SmolVLA). The fixed batch plan is the control; per-rollout policy RNG would need LeRobot internals patched.
  9. LIBERO fixture drift. Re-resetting one env object moves fixtures in 4/20 tasks (7.2 mm stove). Mitigated by one env per rollout, and now detectable per record through t0_model_sha256.
  10. Operation-level return choices belong to the attribution feature: rmst60_op_cap is pessimistic by declaration; a KM-consistent imputation would keep the KM identity but can rank an abandoned attempt above a slow completed one.
  11. The HRT return's linearization is the planner's derivation, passing AC6.2 narrowly (9.51% ≤ 10%); re-derive against CUPID §D.2.
  12. The 2.9 h replay wall time (10,405.7 s against a planned 2–3 min) and one 980 s hashing stall are unexplained; neither reproduced (median 3.9 s per demo).
  13. The v1 fence is recorded but not enforced at method entry points: screening and attribution must call lineage.assert_blind.
  14. Open decision (PoC §10): which metric is the declared headline objective for curation. This feature keeps all of them, each labelled with its τ.

Unexpected premises found

  • LIBERO runs on macOS. LeRobot's docs say it needs Linux; predicates, offscreen rendering and full rollouts ran on this Mac (M4 Pro).
  • LIBERO's reward is hard-coded. create_dataset.py writes rewards[-1] = 1 unconditionally, so it is not a goal check. "No failed demos" now rests on the 1000/1000 replay.
  • duration_s overstates T. Demos record a 10-step success hold and more; the goal first holds 9–82 steps before the last stored state.
  • Also: PhAIL's prose vs its released macro-KS (OpenPI–ACT); PhAIL's croissant.json says 352 fine-tuning episodes, the bucket and paper say 449; two PhAIL sidecars disagree on pooled RMST; LeRobot's LiberoEnv stops at 990 policy steps (inner horizon 1000); LeRobot's init-state assignment depends on batching.

How to read the code

  1. docs/dataflow.md: Steps 2–4. This feature is Step 2, Step 3's input and Step 4's gate.
  2. vlapoc/metrics_registry.py: the vocabulary. Every PoC metric, its declared functional, family, return column and verdict test.
  3. vlapoc/third_party/__init__.py, then a skim of phail_stats.py: episode_to_T_pairs (censored tails, T = ∞ ghosts) and kaplan_meier.
  4. vlapoc/evaluation.py: Episode and arms, every scalar as a functional of the KM CDF, macro-KS, the clustered bootstrap.
  5. scripts/phail_validate.py: the evidence that step 4 is right, on PhAIL's data.
  6. vlapoc/libero_goals.py: LIBERO's goal check, the demo replay, and operations_from_trace.
  7. scripts/human_reference.py: the fixed human anchor (human_reference.parquet, human_operations.parquet).
  8. vlapoc/rollouts.py: start at RECORD_COLUMNS, then run_rollouts, then ProbedLiberoEnv.
  9. vlapoc/runs.py, section "the eval stage": eval_run, the batch plan, the attribution-grade check.
  10. vlapoc/returns.py: one return per metric per rollout (W) and per operation (O), and the empty episode × metric frame.
  11. vlapoc/verdict.py: the two-step gate; verify_run records it.
  12. scripts/lineage_dry_run.py, function eval_smoke: the whole chain in one place.
  13. vlapoc/subset_stats.py, vlapoc/lerobot_train_entry.py: per-subset normalization.
  14. The S0 leak fix: vlapoc/lineage.py, section "blindness of derived versions", and vlapoc/derive.py's module docstring.
  15. scripts/verify_*_s0..s8.py: one script per story; each function names its AC.

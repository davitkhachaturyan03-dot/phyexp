S4 · Per-sub-task time-to-success T for libero_10

A long-horizon LIBERO task now yields one time per sub-task, not only one per episode. One rule turns LIBERO's goal-conjunct trace into PhAIL-style (T, E) pairs. It runs on the 500 libero_10 human demos (950 operation samples, Σ T_k = whole-task T in 500/500) and on every rollout.

ACs 6/6 met Depends on S3, S1 Required story owner decision 7

Why

"T = time (or steps) to task success per episode; for long-horizon LIBERO-10 tasks, per sub-task." — PoC §3.5 A, p. 7
"Operation-level (T, event) pairs give several outcome samples per rollout" — PoC §3.4, p. 7

Owner decision 7: build it in this feature, as its own story. PhAIL's own unit is the operation, one placement among several per episode (PhAIL §3.1 p. 4). The libero_10 analogue is a goal conjunct.

What was built

File / functionWhat it does
vlapoc/libero_goals.py::operations_tableStatic, from LIBERO's BDDL parser: goal conjuncts, maintained conditions (goal ∩ :init) and the number of operations.
vlapoc/libero_goals.py::operations_from_traceThe single rule, declared in its docstring:
  • Operations are the goal conjuncts that are false at t0. Conjuncts already true at t0 are maintained conditions (libero_10 task 8's (turnon flat_stove_1)).
  • Operation k < n completes at the first step where at least k operation conjuncts hold at once. This counts conjuncts, so their order in the BDDL does not matter.
  • Operation n completes at the env's own _check_success step, so the last operation time is the whole-task T by construction.
  • T_k = t_k − t_{k−1}. An unfinished rollout adds one censored tail, built through PhAIL's episode_to_T_pairs with threshold 0.
scripts/human_reference.py --operationsApplies the rule to the stored S3 traces (no second replay) → human_operations.parquet, 1,450 rows.
vlapoc/rollouts.pyThe second caller: every rollout record carries ops and pairs from the same function.
scripts/verify_operations_s4.pySeven labelled-synthetic traces, plus a grep proving there is one definition and two callers.

Example

A real rollout (SmolVLA, external checkpoint, harness validation only): libero_10 task 8 "put both moka pots on the stove", init state 3, seed 3. The stove is already on at t0, so it is a maintained condition, and the task has two operations (one per pot). From the stored rollout record and operation_returns.parquet:

rollout_id                 op_k  t_start  t_end  T_op_s  event
libero_10/8/init003/seed3     1        0    159    7.95      1     # first pot on the cook region
libero_10/8/init003/seed3     2      159    469   15.50      1     # second pot: env's _check_success fires
                                                   -----
                                     sum = 23.45 s = whole-task T (469 steps / 20)
libero_10/8/init001/seed1     1        0    796   39.80      1     # one pot placed ...
libero_10/8/init001/seed1     2      796   1200   20.20      0     # ... then a censored tail to τ_episode = 60 s

The human demos for the same task take a median 9.05 s [8.75, 9.35] for operation 1 and 10.50 s [10.10, 11.05] for operation 2 (s4_human_operation_stats.csv).

Divergences and limitations

  • Threshold 0, not PhAIL's 0.3 s (declared in the docstring). Sim timestamps are exact; PhAIL's 0.3 s multi-grip clustering exists for annotation jitter. Simultaneous completion gives T = 0 under both conventions.
  • Per-sub-task T is family O, not the headline attribution family (plan r2, "Declared functionals"). Family W (whole-task T) is declared for returns and the verdict, because the returns are per rollout (§9.1 Step 3 p. 19). A per-rollout sum of KM-consistent per-operation terms would rank a rollout that made progress below one that made none (inferred, worked example in the plan). Family O keeps its own verdict and its own operation-sample return.
  • Two operation functionals. The descriptive per-operation KM (rmst60_op, unfinished attempts censored: 36.99 s on libero_10:8) and the attribution functional rmst60_op_cap (an unfinished attempt counts as the 60 s cap: 38.15 s). The _cap form is pessimistic by declaration (plan R16), so a slow completed operation can never be outranked by an abandoned one.
  • Clustered CIs can be narrower here. For the pooled per-task median, the episode-clustered CI was narrower than the per-operation one in 6 of 9 two-operation tasks (ratio 0.405–0.900). Each demo contributes exactly one op 1 and one op 2, so resampling demos acts like stratification (inferred). The PoC rule (resample whole episodes) is applied regardless.

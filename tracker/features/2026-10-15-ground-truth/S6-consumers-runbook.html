S6 · Trainable locally, and the server runbook

v3 trains and evaluates with the existing pipeline on this Mac (a 2-step SmolVLA smoke run), and everything that needs a server (does the corruption hurt a trained policy?) is written down as a runbook, not claimed.

ACs 6/6 Depends on S4, S5 Pending server GT-R1 to GT-R6

Why

A ground-truth dataset is only useful if the rest of the pipeline can consume it and if the PoC's causal claim (the corrupted data hurts the policy, and removing the corrupted episodes helps) can eventually be tested. This Mac cannot train SmolVLA at scale or run 1000 rollouts, so this story proves what can be proved locally and writes the rest down so a server operator can run it without guessing. The decision of whether the injection changed the policy belongs to the significance gate, not to eyeballing.

Verify before claiming. Retrain with the disputed episodes restored and show the speed metric improves significantly … — §8.10, p. 18
Each of these is a close comparison between two policies, so use the PhAIL significance gate (Section 3.4) to decide whether the change is real before claiming it. — §2.6, p. 5

What cannot be shown here. (1) Whether any corruption actually hurts a trained policy, which needs SmolVLA training and rollouts: GT-R1 to GT-R5. (2) Per-type harm: one combined version gives one pooled injected arm; seven arms would be needed (design D2). (3) LIBERO has no ghost-event (drop) rule (evaluation decision 6), so the gripper-release "drops" hypothesis can show up only as lower success, a lower F(τ) or more timeouts, never as a drop rate. Do not look for one in the GT-R4 output. (4) The §4.5 metric check (idle padding should move time metrics, gripper release reliability) needs per-metric attribution, which is a later feature; the labels already carry the hypothesis.

Divergences and limitations

  • Known issue for the attribution feature. train_run and eval_run do not call open_for_method or assert_blind. Correct for this feature's injected and oracle training arms; a gap for any later method that trains policies. The attribution feature must route its training inputs through the loader. Not fixed here (R11).
  • Smoke scale only. A 2-step fine-tune proves the data reaches the trainer with the right normalisation, not that a policy learns anything from it.
  • The smoke run started from smolvla_base with load_vlm_weights=False, as the evaluation feature's S8 did (the 2.03 GB backbone download was not approved).
  • The runbook's disk and time figures for server steps are inferred (for example about 4 h per seed on one A100, quoted from the LeRobot SmolVLA docs, unmeasured on our server).

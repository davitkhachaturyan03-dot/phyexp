S3 · Dataset versions, named splits and subsets that resolve to LeRobot episodes=

A dataset version is now identified by its content (dataset_version_id). A held-out clean reference split (40) and a candidate split (960) are persisted. Every selection a later stage makes (drop top-k, drop k random, drop a group, a random subset) is a recorded child subset that LeRobot can load exactly.

ACs 9/9 met Depends on S2 Store data/lineage/{versions,subsets,splits,names.json}

Why

Runs must be tied to exact dataset versions, and the screening and injection stages need a clean reference set that is never corrupted. The counterfactual and causal-baseline stages each train on a subset: drop top-k, drop k random, drop one group, or many random subsets. The record has to say how each subset was derived.

References "are a small, held-out set of clean demonstrations for the target task, separate from the candidate data being audited." — §8.3, p. 14
"Treat LIBERO's original demos as clean; corrupt only the training copy" — §8.7, p. 15 (row "Benchmark demos (PoC)")
"Remove the top-k most harmful episodes and retrain. As a control, remove k random episodes and retrain." — §9.1 Step 4, p. 19 · "Leave-one-group-out ablations. Drop one data source or task group, retrain, and measure the change." — §2.1 item 5, p. 3

The reference size comes from RoboDrop App. A.1 (p. 13): "we reserve two uncorrupted episodes per task" (quoted; docs/papers/RoboDrop_Gradient_Compatibility_arXiv-2609.10021.pdf).

Divergences and limitations

  • R1: a subset is a selection in the record, but loading it costs disk. LeRobot loads episodes= through Dataset.from_parquet(filters=…) (lerobot/datasets/io_utils.py:79-82, quoted), and HF datasets writes an Arrow cache per distinct episode list: measured 6.6, 6.4 and 6.5 GB for the three S6 training subsets. Streaming is no way out, because StreamingLeRobotDataset stores episodes but never filters on it (quoted source, analyzer measured). This is the main blocker for many-subset training (see the report's open decisions).
  • files.json identifies a physical copy, not content. LeRobot parquet files are not byte-reproducible, so verify_version is a tamper check. dataset_version_id is the content identity.
  • No episode-table digest. version.json does not digest the episode_index → episode_id table that resolve() depends on. An edit to it would go unnoticed at training time (analysis-r2, non-blocking).
  • Re-registering content under a new name rewrites that version's record name. After registering v0's content as v0copy in a scratch store, resolve_version("v0") returned a record named v0copy (refactorer, measured; now documented in the docstring).
  • libero_task_id is suite-relative. drop_group(parent, "libero_task_id", 2) drops one task from each suite (96 episodes, analyzer measured). Use task_name for leave-one-task-out.
  • References accept prefix ids of 8 or more hex characters. The refactorer deduplicated the resolver but left prefix matching in place: removing it is the owner's call.

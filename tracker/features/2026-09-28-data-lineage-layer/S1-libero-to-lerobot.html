S1 · Convert raw LIBERO into one LeRobot v3 dataset, unfiltered

All 1000 human demonstrations of libero_spatial and libero_10 now sit in one LeRobot v3 dataset (200,340 frames), stored losslessly. Every stored frame equals the raw frame rotated 180°.

ACs 7/7 met Depends on none Dataset data/lerobot/libero_spatial_10/ (v0)

Why

The first milestone asks for LIBERO in a form SmolVLA can train on, and the episode catalog builds on LeRobot's format. The owner asked for "a dataset … that will enable all downstream tasks inside the poc" (brief.md).

Foundation: "Lineage tracking; episode catalog; LIBERO (one or two suites) + SmolVLA" — §10, p. 20
"LeRobot's dataset format plus a Parquet metadata table works well." — §2.2, p. 4

Divergences and limitations

  • Four deliberate divergences from the hub LIBERO datasets (stated in the module docstring): all 1000 demos at full length, not the hub's 811; native 128×128, not a 256² re-render; fps 20, not 10; lossless PNG, not AV1 video. The content hash in S2 relies on the lossless storage.
  • Resolution is a decision for the evaluation feature. Rollouts must render at 128. LeRobot's LiberoEnv config defaults to 360 (quoted in plan.md). Published SmolVLA/π0 LIBERO numbers used the 256² hub data, so absolute success rates may differ (inferred).
  • AC1.2 was reworded in round 2. Against lerobot/libero the image dtype is necessarily image rather than video, because the dataset is lossless. The analyzer accepted the rewording as matching what was built.
  • LeRobot's writer leaves an empty images/ staging tree behind. convert() now removes it after finalize(), so the committed converter differs from the code that ran by those 4 lines (execution log).
  • PyAV's bundled libavdevice clashes with Homebrew ffmpeg and prints an objc warning on import (measured). No crash was observed.

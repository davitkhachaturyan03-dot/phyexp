S6 · Every downstream stage type, end to end, on the real data

One script recorded the PoC's whole chain as 14 MLflow runs on the real v0/v1 data: build → split → derive → screen → train ×2 → eval → attribute → select ×2 → train ×2 → eval ×2. The trains are real (if tiny) LeRobot runs; screening, evaluation and attribution are labelled stand-ins. Every run names the episode versions it used.

ACs 7/7 met Depends on S4, S5 Chain dry-run-k20-s0-20260929T074215Z · git 7effd25

Why

The owner's requirement is that the layer "will enable all downstream tasks inside the poc" (brief.md). The way to show that before those stages exist is to run each stage type once, with its real inputs and outputs, and check that lineage names exactly what each one consumed.

Step 3 input: "The training dataset, the trained policy, and the rollouts from Step 2." · Step 4: "Remove the top-k most harmful episodes and retrain. As a control, remove k random episodes and retrain." — §9.1, pp. 18–19

Divergences and limitations

  • Three stages are stand-ins only: screening (scores NaN), evaluation (a rollout plan with outcome = not_run; the checkpoint is really loaded, with 51,600,263 params, strict) and attribution (scores = sha256 of the key mapped to [0, 1)). They prove the lineage contracts and nothing about outcomes.
  • The trains are 5-step ACT smoke runs on MPS (16.3 / 7.5 / 12.2 / 25.8 s), not SmolVLA. They prove the path from data to trainer to checkpoint, not training quality.
  • 3 of the 20 episodes dropped by top-k were corrupted. The placeholder scores are a key hash, so this is chance, not attribution.
  • The chain's build, split and derive runs were recorded by the S4 commands and reused, which is possible because the entities are content-addressed.
  • The main store holds 15 runs: the 14 chain runs and one inert FAILED split attempt (an MLflow import bug, fixed in 398e037). Queries use FINISHED runs only.
  • Disk: the 4 checkpoints take 2.3 GB under data/runs/, and the three distinct training subsets made 6.6 / 6.4 / 6.5 GB of HF cache (R1).

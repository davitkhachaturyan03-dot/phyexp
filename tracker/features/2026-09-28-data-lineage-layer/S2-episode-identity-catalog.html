S2 · A stable ID, a content hash and a §2.2 catalog row for every episode

Each of the 1000 episodes has an episode_id taken from the raw source and a sha256 content_hash of its decoded content. The hash computed from the stored dataset equals the hash recomputed from raw HDF5 for 1000 of 1000 episodes.

ACs 7/7 met Depends on S1 Output data/lineage/catalog/libero_spatial_10/episodes.parquet (1000 × 21)

Why

Lineage needs to name exactly which episode, and which version of it, a run consumed. LeRobot's episode_index cannot do that, because LeRobot's own edit tools renumber it. The catalog columns are what per-episode attribution scores get aggregated by later. duration_s is the human reference that the evaluation layer's HRT metric needs.

"Every training run should be tied to exact dataset versions (content hashes), episode IDs, …" — §2.1, p. 3
"Each episode gets a stable ID and a metadata row: source, task, language instruction, scene, objects, operator, collection date, episode length, and basic action statistics (smoothness, idle time, gripper toggles)." — §2.2, p. 4
"Human reference = durations of LIBERO's original human-teleoperated demonstrations on the same tasks." — §3.5, p. 8

What was built

File / functionWhat it does
vlapoc/catalog.py::episode_id_of"<suite>/<task_name>/demo_<k>" from the raw file and robomimic demo key; the same demo_k key CUPID's released code uses.
vlapoc/catalog.py::episode_content_hashThe only hash function in the system: sha256 over the task string, then per frame the float32 action, float32 state and both decoded uint8 images. Bookkeeping columns are excluded.
vlapoc/catalog.py::hash_stored_datasetThe stored side: decodes the PNGs from the LeRobot parquet (8 processes) and hashes each episode.
vlapoc/catalog.py::scan_raw, _raw_file_workerThe raw side: re-hashes every demo straight from HDF5, and checks rewards, init_state and the control rate.
vlapoc/catalog.py::action_statsSmoothness (mean ‖Δa[:6]‖), idle fraction (steps whose six arm dims are exactly 0) and gripper toggles. No invented thresholds.
vlapoc/catalog.py::build_catalogJoins the two sides into one row per episode and runs the 1000/1000 checks; writes episodes.parquet, raw_files.parquet and catalog.json.

The hash byte layout, from the module docstring:

b"vlapoc.episode.v1\0"
uint64-LE byte length of the task string, then the task string (UTF-8)
uint64-LE number of frames
for each frame, in order:  action float32-LE ×7 · observation.state float32-LE ×8
                           · image uint8 128×128×3 (decoded pixels) · image2 uint8 128×128×3

The pixels are hashed after decoding, deliberately. Two conversions of the same demos wrote different parquet bytes, because each file embeds a random HF datasets fingerprint, yet identical decoded content (measured, execution log finding 2). A per-file md5 in the style of DVC would report a "new dataset" on every rebuild.

Divergences and limitations

  • Three §2.2 columns LIBERO cannot fill. operator and collection_date are null, because LIBERO publishes neither (LIBERO p. 6). libero_spatial's scene is the raw problem_name (one value for all 10 tasks); libero_10's is the <ROOM>_SCENE<n> prefix. objects lists every object in the scene, distractors included, because §2.2 doesn't qualify the word.
  • §3.5 asks for per-sub-task T on libero_10. Only the whole-episode duration is catalogued. Per sub-task needs BDDL predicate replay, which the evaluation feature owns. The PoC itself calls the reference approximate: "demos and rollouts don't share initial states" (p. 8).
  • What the 1000/1000 match proves. The raw-side re-hash reuses the converter's load_raw_episode, so it proves storage fidelity. The mapping itself (rotation, cast, state layout) is proven independently only on the 6 episodes of AC1.3/1.4, plus the analyzer's 10.
  • libero_task_id is suite-relative (0–9 in each suite). Use task_name to name one task across suites (see S3, drop_group).
  • Not tested: hash determinism on x86 Linux. Little-endian float32 and decoded pixels are platform-independent by construction (inferred). The first run on the GPU box should run python -m vlapoc.lineage version recompute v0.

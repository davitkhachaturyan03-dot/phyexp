Data layer + lineage layer

The PoC now has its dataset and its record-keeping. All 1000 LIBERO demonstrations of two suites sit in one lossless LeRobot dataset, each episode with a stable ID and a content hash. A corrupted copy is a new version with its ground truth kept apart. Every stage, from conversion to retraining, is an MLflow run that names exactly which episode versions it used. You can ask "what changed between these two runs?" and get an episode-level answer.

Grounding

Spec section

Papers
RoboDrop App. A.1 (p. 13): the reference size, "two uncorrupted episodes per task", and the demo corruption, "Gaussian noise with standard deviation 0.25σa". LIBERO p. 6: the catalog's source (50 demos per task, SpaceMouse teleoperation). CUPID's released code addresses demos as demo_{i}, so every episode keeps source_file/source_demo. Prior art
Adapter over LeRobot v3 (the dataset) plus MLflow (the runs). The hub datasets lerobot/libero and HuggingFaceVLA/libero were rejected: they hold only 811 of our 1000 demos (OpenVLA's filter, whose premise is false here), 68 shortened, at fps 10, with no map back to raw demo IDs. LeRobot's format and writer are used as is, but its episode identity is positional and it has no content hash, parent links or labels. W&B Artifacts needs an account; its use_artifact raises in offline mode. DVC hashes files, and LeRobot parquet files are not byte-reproducible (measured). The custom code is only what none of them provide: the episode_id + content_hash identity, version and subset manifests, derivation labels, the selection ops and the lineage queries. The analyzer's audits in both rounds found nothing to swap in (Process trail).
Implements
The whole §10 "Foundation" row except SmolVLA training: lineage tracking, the §2.2 catalog, two LIBERO suites. Also the mechanism under the "Ground truth" and "Causal baseline" rows: derived versions with labels, the reference guard, length-changing edits, recorded drop-top-k (harmful and helpful), random-k, group leave-one-out and random-subset selections. The §3.5 human reference durations. The §9.2 key contract: every score table keyed by (episode_id, content_hash).
Diverges
All 1000 demos, not the hub's filtered 811. Native 128², fps 20, lossless PNG (hub: 256², fps 10, AV1). Owner-approved: MLflow local as the backend (Q1); git local only (Q2); the full §2.5 corruption suite deferred to a separate feature, with only the mechanism and one RoboDrop transform here. Training goes through LeRobot's train() via an entry point, because the lerobot-train CLI is broken on Python 3.14 (draccus #69); lerobot 0.6.1 declares only Python 3.12/3.13.

Open decisions and known issues

For the features that build on this one. None blocks this feature's ACs; several block or shape the next features.

  1. Normalization-stats leak (training feature decides). LeRobot normalizes with the version's full meta/stats.json, computed over all 1000 episodes: the 40 references, the 100 corrupted and any episodes a selection dropped. All four S6 checkpoints share those stats (measured). That conflicts with "data is the only variable" (p. 1) unless it is declared. The options are fixed reference stats or per-subset stats (recompute_stats on a copy). Each run records stats_json.sha256, normalizer.sha256 and a normalization_stats param, so either choice stays visible.
  2. About 6.5 GB of HF cache per distinct training subset. With the current loader, many-subset datamodels training (DataMIL used m = 10⁴) and 20 leave-one-task-out runs are infeasible. The project cache is already 27 GB, with 118 GiB free. A lead for the training feature (inferred, untested): LeRobot's trainer already restricts episodes in its sampler (EpisodeAwareSampler(episode_indices_to_use=…), lerobot_train.py:457-465). Loading each version once and passing the subset only to the sampler would bring the per-subset cost to about 0. Streaming is no way out: it ignores episodes.
  3. Noised actions leave Box(−1, 1) (clip: null). 51% of corrupted frames are out of range, and the gripper is continuous, so gripper_toggles is meaningless for corrupted episodes. Clipping is the injection feature's call.
  4. libero_task_id is suite-relative (0–9 per suite). Group by task_name.
  5. A refused drop_group leaves a FAILED run, because column and value are validated inside the run. It is inert, since only FINISHED runs form edges.
  6. The select.dropped tag is truncated at 7,900 characters. The subset file is the record of truth.
  7. No episode-table digest in version.json. The plan-mandated in-place rewrite of v1's tables (removing the leaked label) left no trace in the store.
  8. LeRobot's task_index order depends on PYTHONHASHSEED in derived datasets (dataset_tools.py:549). Content hashes and version ids are unaffected; file digests and task_index stats of a re-derivation will differ.
  9. Registering already-registered content under a new name rewrites that version's record name (refactorer, measured in a scratch store).
  10. Screening, evaluation and attribution are stand-ins only. No outcome number exists yet. The selections' "scores" are placeholders. Updated 2026-10-11: evaluation is now real (evaluation layer: LIBERO rollouts, per-metric returns, the macro-KS gate); screening and attribution are still stand-ins, and the scores are still placeholders.
  11. Environment. Python 3.14 vs lerobot 0.6.1's declared 3.12/3.13. SmolVLA training should use a 3.12/3.13 venv or keep the entry point. There is no dependency manifest in the repo. Evaluation must render at 128² and confirm that LeRobot's --env.task_ids follows the same task order (R6). MLflow stores absolute paths in its own records.
  12. Cleanup the owner may want: data/lineage_scratch/ (2.3 GB; still holds a stale v1 table with the leaked column, read by nothing) and data/scratch/r2_strip_label_column.py.
  13. (2026-10-02) Answer-key leak in v1, found after release. Methods could identify the 100 corrupted episodes without the labels in two ways. First, parent_content_hash differed from content_hash for exactly those rows (AC4.1 required that column). Second, row order: merge_datasets appended them as episode_index 900–999, in their own data files 73–80. The fix is evaluation-layer S0, under owner ruling A. derive_version now keeps parent order, the pre-edit hashes moved to the lineage-only parents.parquet, and check_blind guards every derivation. v1's tables lost the column. Its version id is unchanged, and it is fenced from method use (check_blind(v1) = ['episode_index']). It stays valid as lineage evidence. Details are in changelog.md.

  • Evaluation layer: KM time-to-success CDFs, ghost events, censoring, HRT and macro-KS. The HRT reference is the duration_s column (superseded 2026-10-03 by T_success_s, evaluation-layer S3). The eval run contract (checkpoint hash, suites, task ids, init-state indices, seeds) is in place; the rollouts themselves need the LIBERO simulator (Linux), rendered at 128².
  • Ground truth: the injection experiment, which is the owner-approved separate feature. It needs the corruption suite on derive_version (time shifts in steps: RoboDrop's 2 s = 40 steps at fps 20), a clipping decision, and scoring against labels.parquet.
  • Causal baseline: group leave-one-out is recordable today (select_run(op="drop_group")); training 20 such subsets waits on the cache fix (Open decision 2) and the macro-KS gate.
  • Fine-grained attribution (fork CUPID): scores keyed by (episode_id, content_hash) pass check_scores. source_file/source_demo map every episode back to CUPID's demo_k keys.
  • Verification & demo: drop top-k harmful and helpful (direction) and drop k random are recorded selections; diff and trace explain each retrain.

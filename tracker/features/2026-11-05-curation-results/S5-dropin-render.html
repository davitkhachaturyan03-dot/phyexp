S5 · Drop-in proof and real-browser checks

The page renders a chain built from the server's own commands with no code change, and its plots are the right size in real Chrome.

ACs 5/5 Depends on S1 to S4 Data demo is SYNTHETIC; no real Round A yet

In plain words

A demo on invented data proves little unless real server results will show up in the same page. This story builds a tiny chain by running the server's actual Round A commands (the dry run's select, verify and step4-summary commands) through the same stage tool the server uses, on a toy fixture. The page must then show exactly what was recorded. A second check re-labels that chain the way the server would write it and confirms the SYNTHETIC and SMOKE banners disappear and a REAL caption appears; adding one synthetic tag brings the banner back.

The same story checks the page in a real browser (headless Chrome at 1400 px) so that plots are not collapsed, and re-runs the older checks to make sure nothing else changed.

Terms are defined in the glossary of the main report.

Why

PoC §10 (p. 20) wants the verification step demonstrated; the brief demands that real Round A runs render with no code change and that the real-browser check covers the new page. Round 1 of the analysis added family O here, because the server records 21 operation-level verdicts and the page had been hiding them.

Divergences and limitations

  • The fixture's own subset is the parent and the removal size is scaled (5 per task stays, 20 overall becomes 3, in the 20-task fixture). Commands are otherwise the dry run's. This proves the shape of server output, not its numbers.
  • Recorded change to a checker: --demo check 6.5 used to fail when the laptop had under 20 GiB free disk (it passed at 20.25 GiB and failed at 17 to 19 GiB; the demo store is 17 MiB). The refactor made store plus cache under 2 GiB the check and turned free disk into a printed [WARN]. --demo went from 5/6 to 6/6 with no change to the demo.
  • Open (N8): runbook check 8.5 will fail again if the owner commits a CLAUDE.md edit after bad0241, because agents commit under the same git user. Fix by advancing claude_md_base_commit.txt or by ignoring commits without the Claude co-author trailer.
  • No streamlit or Chrome process was left running after the checks.

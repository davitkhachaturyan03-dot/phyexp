S8 · Server runbook skill

A 15-step guide, loaded automatically by a Claude Code session on the GPU server, from preflight to bringing results back, stopping to ask the owner at 13 marked points.

ACs 9/9 Depends on S4, S5, S10 Data scores SYNTHETIC, no real results yet

In plain words

The owner wants to run the whole pipeline on the real GPUs from a fresh Claude Code session that knows nothing about this repo. The runbook is a skill file that session loads on its own. Every step says what to run, what output to expect, and when to stop and ask. Because we cannot run the server steps here, every step is honestly tagged: checked here (the commands and counts were run locally) or unchecked until a server session.

Terms are defined in the glossary of the main report.

Why

Owner request: "an exact step-by-step runbook for a new claude session inside the actual gpu server ... all the way to attribution and real dashboard creation". It makes Round A (v3), the clusters stage, the dashboard and both Round B variants runnable by someone else.

"In case I want to run the pipeline end-to-end on real gpus the claude-code session must know exactly what to do with this code." — owner, 2026-10-22 (brief.md)

Divergences and limitations

  • Ten of 15 steps are unchecked until a real server session. Their expected outputs are labelled inferred or quoted, never measured.
  • Known server-only risks recorded in Step 15: SQLite locking under concurrent jobs, and the smolvla_base revision 5e8d12a6 versus the pinned d9f33c94.
  • Step 2 copies the smoke checkpoint (data/runs/train-smolvla-2step-persubset-v0ref-20261005T012854Z/, 1.5 GiB) because Step 3 loads it; the analyzer found it missing in round 2.
  • The GPU-hour figures (about 4 h per training) are inferred.
  • The repoint script is kept rather than replaced by mlflow-export-import, which does not preserve run ids (see the reinvention audit in the main report).

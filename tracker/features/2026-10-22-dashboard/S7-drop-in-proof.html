S7 · Real runs drop in with no code change

A proof that the app shows a real run exactly as it shows a synthetic one: only the recorded tags change the banner.

ACs 3/3 Depends on S5, S6 Data scores SYNTHETIC, no real results yet

In plain words

The demo is only worth showing if the real thing will look the same. This story tests that claim directly. It runs the real attribution, ensemble and cluster code on a fixture, opens the result in the app, then changes only the recorded tags (as the server will) and checks that the banner goes away. Adding back a single synthetic tag must bring it back. The code files do not change in between: a git check shows the working tree is identical before and after.

Terms are defined in the glossary of the main report.

Owner answer: real server results must drop in later with no code change, and the SYNTHETIC label disappearing only when the data is real.

Divergences and limitations

  • This proves the app and loaders accept real-shaped runs. It does not prove the server produces runs with those tags; the server writes them by design (vlapoc.smoke=false, eval.attribution_grade=true) and the runbook has a stop-and-ask if the real results still show SYNTHETIC or SMOKE.
  • The fixture's scores are synthetic, so the proof is about display and labelling, not about numbers.

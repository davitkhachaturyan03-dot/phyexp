S3 · Score clusters against the planted types

After clusters are found, a separate step checks how well each one matches the planted corruption types, and cannot influence the discovery.

ACs 4/4 Depends on S2 Data scores SYNTHETIC, no real results yet

In plain words

We planted damage in 91 recordings, so we can ask: does a discovered group contain the damaged recordings? This story does that comparison. It is kept separate on purpose. The cluster stage never opens the answer key, and the scoring step runs afterwards and only reads the finished cluster run. That way a good match means the method found something, not that it peeked.

Terms are defined in the glossary of the main report.

Why

PoC §2.1 item 4 asks to inject corrupted episodes and "check whether your attribution method flags exactly those". §4.5 asks whether each corrupted group is assigned to the expected metric.

"Inject 5–10% corrupted episodes and measure how many the method ranks near the top." — §2.1 item 4, p. 3

Example

A hand-built synthetic cluster (13 idle_padding episodes plus 13 clean ones) scored against the real answer key. Fisher's exact test asks how unlikely such an overlap is by chance.

cluster: 13 idle_padding + 13 clean episodes (26 members), type idle_padding has 13 of 960
precision = 13/26 = 0.5     recall = 13/13 = 1.0
lift = 0.5 / (13/960) = 36.923     one-sided Fisher p = 1.195e-22
against the pooled 'any planted' (91): recall 13/91 = 0.143
a clean-only cluster: overlap 0, p = 1.0
(verify_dashboard.py --planted, check 3.2)

Divergences and limitations

  • The output also has a pooled "any_planted" pseudo-type (all 91 together) beside the seven types.
  • On the demo store some synthetic clusters overlap real planted types strongly (smallest p about 1e-11). That arises because the invented structure is built from descriptors (task-relative length, smoothness) that also describe the real corruptions. It is not evidence about attribution. The page shows it under the SYNTHETIC banner and the heading "ground-truth check (answer key read after discovery)".

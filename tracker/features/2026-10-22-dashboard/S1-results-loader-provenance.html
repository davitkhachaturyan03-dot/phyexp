S1 · Read side and the fail-closed label

One loader reads results back from the lineage store, the missing influence matrix is now recorded, and every number is labelled SYNTHETIC, SMOKE or REAL from the runs behind it.

ACs 6/6 Depends on — Data scores SYNTHETIC, no real results yet

In plain words

The dashboard needs two things the pipeline did not provide. First, for one failed test attempt it must know how strongly each training recording pushed it. That table (the influence matrix) was computed and then thrown away. Second, a stakeholder must never mistake invented scores for real ones. So this story saves the matrix, adds one reader for everything the app needs, and decides the label by looking at every run behind a number. If any tag is missing, the label is not REAL.

Terms are defined in the glossary of the main report.

Why

PoC §2.7 asks for "the most influential training episodes" for a selected rollout; that needs the per-rollout row. The owner's rule is that real server results must replace synthetic ones with the SYNTHETIC label disappearing only because the data is real.

"A dashboard: select a failed rollout, see its failure type, the most influential training episodes (with video) and their source datasets" — §2.7, p. 5

Divergences and limitations

  • REAL additionally requires at least one training run and one evaluation run in the trace (otherwise the chain is not fully recorded). This is a stricter reading of the plan and is disclosed in the execution log.
  • The rule uses eval.attribution_grade=true as the plan says; the stricter …asserted tag some verdict code uses is not required (one condition to add later).
  • Ensemble runs have no matrix of their own (they average per-seed scores); the Rollouts page therefore picks one seed run.

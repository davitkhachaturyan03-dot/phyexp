S10 · The §9.2 claim as retraining arms

The plan and code to test "bad but not harmful" causally: retrain without each planted type, without the most harmful clean episodes, and without all 91, against random clean controls.

ACs 6/6 Depends on S4, S9 Data scores SYNTHETIC, no real results yet

In plain words

S9 only reads influence scores, which are estimates. To say a damage type genuinely does not hurt the policy, the data must be removed and the policy retrained. This story builds that test: seven arms (one per damage type, 13 episodes each), one arm removing the most harmful clean-looking episodes, a random clean control, and an arm that removes all 91 damaged episodes as a positive control. Each retraining uses the same recipe and three seeds. The verdict wording is careful: a null is reported as "no detectable harm, bounded" with the interval, never "harmless", and if nothing shows an effect anywhere the verdict is "inconclusive".

Terms are defined in the glossary of the main report.

Why

PoC §9.2 asks for exactly this comparison; §9.1 Step 4 says estimates must be turned into verified results. The oracle-arm pattern (removing the 91 labelled episodes) already existed in the ground-truth feature runbook (GT-R5).

"Influence estimates can be wrong. This step turns them from claims into verified results." — §9.1 Step 4, p. 19

Divergences and limitations

  • Not run. No Round B has been executed; all verdicts shown anywhere are SYNTHETIC. This story delivers the plan, the code and the proof that the plan is wired correctly.
  • The three seeds share one random control draw per arm, so "k of 3 seeds" is not three independent replicates of the control; --random-draws 2 adds a second draw (+33 jobs, +3 trainings).
  • The oracle positive control removes 91 episodes (owner-approved), so a confirmation there does not show power at 13; the sentence says so.
  • The clean-but-harmful arm needs the ensemble's same-task score column (one episode per task); on real data only tasks with rollouts have it (all 20 in the first server run).
  • The word "harmless" is never used; an all-null result is reported as inconclusive ("with 13 episodes (1.4% of the data) per arm the test may lack power").
  • The hypothesis-to-metric mapping uses the earlier declared recovery.EXPECTED_METRICS, not a parse of the free-text hypothesis.

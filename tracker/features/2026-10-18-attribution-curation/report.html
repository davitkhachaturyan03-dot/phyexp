Attribution, curation and server training

CUPID influence of every training episode on every family-W return, per-task curation with matched random controls, and a SLURM chain of tracked stages. Ported from VLA-data-curation into vlapoc. vla-build single pass — not an analyzer report.

What now exists

vlapoc.influence writes Kronecker-projected per-sample gradients of a SmolVLA checkpoint (117 trainable Linear layers, 7,488 dims, measured). vlapoc.attribution.attribute_run is the real attribute stage: it refuses a fenced training version, requires trajectories and matching feature manifests, and writes an episode × metric table keyed by (episode_id, content_hash). drop_top_k_per_task / drop_random_k_per_task keep identical per-task counts. scripts/server_pipeline.py --dry-run --tag v0cand builds a 74-job chain (train → eval → returns → features → attribute → ensemble → select → retrain → eval → verify).

Recorded divergences

  • Centred returns (inferred). Ψ_R uses (R − R̄); --no-center is CUPID Prop. 1 literally.
  • Per-task drops (inferred). A global top-k can empty one task; curated and random arms drop the same k from every (suite, libero_task_id).
  • Seeded (noise, time) draws. The cluster code seeded only the noise. Two fresh processes drew different times, so its October feature files are not reproducible. Fixed here.
  • Eval-stage numerics. load_checkpoint upcasts 225 of 500 parameters to fp32; LeRobot from_pretrained keeps the file's bf16. Features differ by median 13.5% (min cos 0.857) if dtypes are not matched. Featurize keeps the eval loader on purpose.

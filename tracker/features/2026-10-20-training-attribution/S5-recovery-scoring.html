S5 · Score attribution against the planted ground truth

A scoring stage measures, per kind of planted damage and per metric, how well the attribution scores rank the damaged recordings, next to the best simple statistic that each kind must beat.

ACs 6/6SYNTHETIC scores Depends on S3 Glossary report.html#glossary

In plain words

An earlier feature planted known damage in a copy of the dataset: 91 of 960 recordings, in seven kinds, with an answer key. This story builds the scorer that takes a table of attribution scores and asks, for each kind of damage and each metric, whether the damaged recordings are ranked near the top. The score used is AUROC, from 0.5 (no better than guessing) to 1.0 (perfect) for how well a ranking puts the damaged items above the clean ones; recall@13 is the share of the 13 damaged recordings of one kind found within the top 13.

The spec's §4.5 names two expected pairings (idle padding should show up in the speed metrics, gripper release in reliability). We wrote those pairings into the code and committed them before any scoring code existed, so they are real hypotheses and cannot be tuned after seeing results.

All numbers on this page come from planted synthetic scores: columns built to rank one kind first, and a random column. They prove the scorer works (1.0 where planted, 0.527 for random). They say nothing about whether the real method finds any damage; that needs the server run.

Terms (AUROC, recall@13, answer key, v3, corruption types) are in the report glossary.

Why

PoC §2.1 item 4 and §4.5 want to know whether attribution assigns each corrupted group to the expected metric. The ground-truth feature's limitation D adds that a method only counts if it beats each kind's best simple statistic. Nothing in the ported code scored attribution against the key.

"Check whether attribution assigns each corrupted group to the expected metric" — §4.5, p. 11 (and "These mappings are hypotheses the experiment should confirm")

Example

With the real v3 answer key and a synthetic score table whose harm_rmst60 column ranks the 13 idle-padding episodes first, the idle-padding row for that column reads AUROC 1.0 and matches_hypothesis = True, because the §4.5 hypothesis says idle padding should show up in a speed metric. A random column pooled over all 91 damaged recordings scored 0.527. The recovery table is deleted with the scratch store on purpose: synthetic numbers must not be kept as if they were results.

Divergences and limitations

  • Only two types have a PoC-stated expected metric. The other five have none and are not given an invented one (None).
  • The random-column band [0.4, 0.6] is an inferred band for 91 positives of 960 and is applied to the pooled value only; per type, with 13 positives, a random column's AUROC has a standard deviation of about 0.08.
  • recovery_run wraps groundtruth.score_recovery once per table (one tracked run) rather than score_run once per column (28+ runs). A design choice.
  • Columns containing NaN are skipped and named, since the key contract refuses NaN scores.
  • Not available here: real recovery numbers on v3 (server run).

S3 · Declare what every score column explains, and tie features to their data

Every score column now states which quantity it explains (for example, the chance of finishing within 30 s), and the attribute run refuses features that were not computed on the data it claims.

ACs 6/6 Depends on S2 Glossary report.html#glossary

In plain words

A score of "harmful" means nothing unless it says harmful for what. The spec's rule is that every attribution result states which functional it explains, meaning the exact measured quantity such as "the chance a rollout finishes within 30 seconds" (written F(30)). The ported code recorded only a list of column names. Now every score column has a recorded row naming its metric, time cap, which rollouts it used (all, or only the same task), the sign convention, and whether it was centred.

The same story closes four gaps in what the attribution run records and checks: it logs a fingerprint of every feature file it read, refuses an evaluation in which some rollouts have no recorded trajectory (they used to be dropped silently), refuses to average two seeds that explain different things, and, after the analyzer's first review, refuses feature files that were not computed on the very dataset copy and rollouts it is attributing.

Result: 32 columns, 32 declaration rows in the checked fixture, and every refusal case tested. This matters because a score table is only evidence if you can say what it is about and where it came from.

Synthetic note: the fixture used here is made-up data. It tests the bookkeeping, not any real policy. Terms: report glossary.

Why

PoC §3.4 requires every attribution result to declare its functional; §4.4 asks for every claim to carry its metric and time cap τ; §2.1 item 1 asks that every run tie back to exact data.

"Every attribution result states which functional it explains, following PhAIL's disclosure principle." — §3.4, p. 7

Divergences and limitations

  • rollout_subset takes only all and same_task. The plan listed failure_type=<t> too, but a failure-type column is an indicator return over all (or same-task) rollouts, so that value would misdescribe it; the indicator is stated in return_definition instead. (Related recorded difference: PoC §9.1 Step 3 says "only rollouts with a specific failure type".)
  • select_run writes "undeclared" for score runs without a declaration (the stand-in runs older verifiers use); only the attribution chain's stage.py select insists.
  • Migration: feature files written before round 2 (absolute or other-version dataset_root, for example the October cluster's) are refused, and so is any attribute run made before this story (no functionals.json). Regenerate with stage.py features; editing a manifest by hand defeats the check. None of those files is in this repo's store.
  • The trajectory binding hashes the whole trajectories folder once per attribute run. Not measured at full scale (1,000 rollouts).
